### Детальное пояснение по папкам
#### 1. `MySaaS.Domain` (Самое важное, ни от кого не зависит)
Здесь живут твои "умные" сущности и бизнес-правила.

**Entities/Orders/**:
*   `Order.cs`: Содержит методы `UpdateItems()`, `ChangeStatus()`, `AddTransaction()`, а не просто свойства.
*   `OrderItem.cs`: Value Object для позиций заказа с валидацией.
*   `OrderStatus.cs`: ValueObject с бизнес-логикой переходов между статусами.

**Entities/Tenants/**:
*   `Tenant.cs`: Основная сущность тенанта с валидацией субдомена.
*   `TenantUser.cs`: Пользователь в контексте тенанта.
*   `TenantSettings.cs`: Настройки тенанта (тариф, лимиты).

**Entities/Transactions/**:
*   `TransactionDefinition.cs`: Описывает структуру транзакции (JSON-схемы) с валидацией.
*   `TransactionRecord.cs`: Журнал проведенных транзакций.
*   `TransactionStatus.cs`: Статусы транзакций.

**ValueObjects/**:
*   `Email.cs`: Валидация email адресов.
*   `Money.cs`: Работа с деньгами (валюта, операции).
*   `Subdomain.cs`: Валидация и генерация субдоменов.

#### 2. `MySaaS.Application` (Оркестрация)
Здесь живет **MediatR** и логика "Что делать".

**Features/Orders/**:
*   `Commands/CreateOrderCommand.cs`: Создание заказа с валидацией.
*   `Commands/UpdateOrderStatusCommand.cs`: Обновление статуса с бизнес-правилами.
*   `Queries/GetOrderByIdQuery.cs`: Получение заказа с связанными данными.
*   `Queries/GetOrdersListQuery.cs`: Поиск и фильтрация заказов.
*   `EventHandlers/OrderCreatedEventHandler.cs`: Отправка уведомлений при создании.

**Features/Transactions/**:
*   `ExecuteTransactionCommand.cs`: **Transaction Engine**. Загружает определение, выполняет действия, сохраняет результат.
*   `GetAvailableDefinitionsQuery.cs`: Получение доступных транзакций для текущего статуса.
*   `ValidateTransactionCommand.cs`: Валидация данных перед проведением.

**Features/Tenants/**:
*   `CreateTenantCommand.cs`: Создание нового тенанта с БД.
*   `SuspendTenantCommand.cs`: Приостановка тенанта.
*   `GetTenantStatsQuery.cs`: Статистика по тенанту.
*   `UpdateTenantSettingsCommand.cs`: Обновление настроек.

**Common/**:
*   `Result.cs`: Result Pattern для унифицированных ответов.
*   `BaseCommand.cs`: Базовый класс для команд.
*   `BaseQuery.cs`: Базовый класс для запросов.
*   `Exceptions/`: Специфичные исключения бизнес-логики.

**Interfaces/**:
*   `ITenantService.cs`: Работа с тенантами.
*   `IEmailService.cs`: Отправка email.
*   `IBackgroundJobService.cs`: Фоновые задачи.
*   `ITransactionEngine.cs`: Интерфейс для транзакционного движка.

#### 3. `MySaaS.Infrastructure` (Грязная работа)
Здесь живут детали реализации.

**Persistence/Master/**:
*   `MasterDbContext.cs`: Контекст для базы тенантов.
*   `Configurations/`: Fluent API конфигурации сущностей.

**Persistence/Tenant/**:
*   `TenantDbContext.cs`: Контекст, который динамически меняет ConnectionString.
*   `ITenantDbContextFactory.cs`: Фабрика для создания контекстов.

**Integrations/Marketplaces/**:
*   `Ozon/ApiClient.cs`: HTTP клиент для Ozon API.
*   `Ozon/OzonOrderMapper.cs`: Маппинг данных Ozon в доменную модель.
*   `Wildberries/`: Аналогичная структура для Wildberries.

**Integrations/OneC/**:
*   `ApiClient.cs`: HTTP клиент для 1С REST API.
*   `ExportService.cs`: Логика экспорта данных в 1С.
*   `OneCOrderMapper.cs`: Преобразование форматов.

**Services/**:
*   `EmailService.cs`: Реализация отправки email (SMTP/SendGrid).
*   `DateTimeProvider.cs`: Обертка над DateTime для тестирования.
*   `FileStorageService.cs`: Работа с файлами (S3/локальное хранилище).

**BackgroundJobs/**:
*   `ImportOrdersJob.cs`: Фоновый импорт заказов.
*   `SyncTo1CJob.cs`: Синхронизация с 1С.
*   `ArchiveOldOrdersJob.cs`: Архивация старых заказов.
*   `TenantBackupJob.cs`: Бэкап баз тенантов.
*   `Auth/**:
*   `PermissionPolicyProvider.cs`: Динамические политики авторизации на основе прав.
*   `TenantSeeder.cs`: Наполнение базы данных начальными данными для новых тенантов.
*   `InviteService.cs`: Управление приглашениями сотрудников.
*   `EmailConfirmationService.cs`: Подтверждение email при регистрации.
*   `IdentityService.cs`: Основные операции Identity (регистрация, вход, смена пароля).
*   `TokenService.cs`: Генерация и валидация JWT токенов.

#### 4. `MySaaS.Web` (UI и Вход)
Здесь живет Blazor Server и контроллеры.

**Components/Pages/Orders/**:
*   `OrderList.razor`: Таблица заказов с фильтрацией.
*   `OrderDetail.razor`: Детальная карточка заказа.
*   `TransactionModal.razor`: Динамическая форма по JSON-схеме.

**Components/Pages/Tenants/**:
*   `TenantList.razor`: Список тенантов (админка).
*   `TenantDetail.razor`: Детали тенанта.
*   `CreateTenantModal.razor`: Форма создания тенанта.

**Controllers/**:
*   `WebhookController.cs`: Вебхуки от маркетплейсов.
*   `ApiController.cs`: REST API для внешних интеграций.

**Middleware/**:
*   `TenantMiddleware.cs`: Определяет тенанта по subdomain.
*   `ExceptionHandlerMiddleware.cs`: Глобальная обработка ошибок.
*   `RequestLoggingMiddleware.cs`: Логирование запросов.

**Extensions/**:
*   `ServiceCollectionExtensions.cs`: DI регистрация сервисов.
*   `SwaggerExtensions.cs`: Настройка Swagger/OpenAPI.
*   `SerilogExtensions.cs`: Конфигурация логирования.

#### 5. `MySaaS.Shared` (Общие контракты)
*   `DTOs/`: Объекты передачи данных между слоями.
*   `Contracts/`: API контракты для внешних клиентов.
*   `Enums/`: Дублирование доменных enums для API.

### Ключевые архитектурные принципы

1. **Clean Architecture**: Зависимости направлены внутрь (Web → Application → Domain)
2. **Vertical Slices**: Код одной фичи лежит в одной папке
3. **CQRS с MediatR**: Разделение команд и запросов
4. **Multi-Tenant**: Динамические ConnectionString и изоляция данных
5. **Domain-Driven Design**: Богатые доменные модели с бизнес-логикой
6. **Result Pattern**: Унифицированная обработка ошибок
7. **Background Jobs**: Асинхронная обработка через Hangfire
8. **Testability**: Dependency Injection и абстракции везде

### Поток данных типичной операции

1. **UI** → `Component.razor` → **Controller** → **MediatR Command**
2. **MediatR** → **Command Handler** → **Domain Entity Methods**
3. **Domain** → **Repository** → **EF Core** → **Database**
4. **Domain Events** → **Event Handlers** → **Background Jobs** → **External APIs**

Эта структура обеспечивает:
- ✅ Изоляцию бизнес-логики
- ✅ Тестируемость каждого слоя  
- ✅ Масштабируемость фичей
- ✅ Чистоту кода и низкую связанность
- ✅ Легкость добавления новых тенантов/интеграций
