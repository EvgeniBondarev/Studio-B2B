Автоматическое развертывание экземпляров 1С (Infobases) — это задача **DevOps уровня Hard**. В отличие от Postgres/MSSQL, где `CREATE DATABASE` выполняется за миллисекунды, 1С требует сложной инфраструктуры: Кластер серверов 1С + СУБД + Веб-сервер (IIS/Apache) для публикации HTTP-сервисов.

Есть **два пути** реализации:
1.  **"Честный" Multi-tenant (1C Fresh):** Одна огромная база 1С, в которой включен режим "Разделение данных" (Data Separation). Все клиенты живут в одной базе, но не видят друг друга. Это стандарт 1С для облаков.
2.  **Отдельная база на клиента (Твой выбор):** Физически создаем новую инфобазу + БД SQL + Публикуем на веб-сервере. Это дает полную изоляцию, но требует мощного железа.

Рассмотрим вариант **№2 (Отдельные инстансы)**, так как он ближе к твоей текущей архитектуре.

### 🧱 Архитектура провижининга (Provisioning)

Нам понадобятся утилиты командной строки 1С:
1.  `rac` (Remote Administration Client) — для управления кластером (создание баз).
2.  `webinst` — для публикации базы на веб-сервере (чтобы работало API).
3.  `ibcmd` или Конфигуратор в режиме агента — для загрузки начальной конфигурации (`.dt` или `.cf`).

#### Схема процесса:

1.  **SaaS:** Пользователь регистрируется.
2.  **Hangfire Job (`OneCProvisioningJob`):**
    *   Генерирует уникальное имя базы (`db_client_123`).
    *   Создает БД в PostgreSQL/MSSQL.
    *   Создает Инфобазу в кластере 1С через `rac`.
    *   Загружает "Золотой шаблон" (`template.dt`) с твоей конфигурацией.
    *   Публикует базу на IIS/Apache через `webinst`.
    *   Создает технического пользователя в 1С (для API).
3.  **Финал:** Сохраняет URL (`https://1c-server.com/client_123`) и креды в `TenantDbContext`.

### 💻 Реализация на C# (Wrapper над утилитами 1С)

Создадим сервис, который умеет выполнять консольные команды 1С.

#### 1. Сервис управления 1С (`OneCAdminService`)

```csharp
public class OneCAdminService
{
    private readonly string _racPath = @"C:\Program Files\1cv8\8.3.xx\bin\rac.exe";
    private readonly string _clusterId = "your-cluster-uuid"; // UUID кластера
    private readonly string _adminUser = "admin";
    private readonly string _adminPass = "secret";

    // Шаг 1: Создание инфобазы в кластере
    public async Task CreateInfobaseAsync(string name, string sqlDbName, string sqlPassword)
    {
        // Формируем команду для rac
        // create --cluster=... --name=client_1 --dbms=PostgreSQL --db-server=... --db-name=...
        var args = $"infobase create --cluster={_clusterId} --name={name} " +
                   $"--dbms=PostgreSQL --db-server=localhost --db-name={sqlDbName} " +
                   $"--db-user=postgres --db-pwd={sqlPassword} " +
                   $"--locale=ru --date-offset=0 " +
                   $"{_clusterId} --cluster-user={_adminUser} --cluster-pwd={_adminPass}";

        await ExecuteCommandAsync(_racPath, args);
    }

    // Шаг 2: Публикация на веб-сервере (чтобы работало API)
    public async Task PublishToWebServerAsync(string name, string publishDir)
    {
        var webinstPath = @"C:\Program Files\1cv8\8.3.xx\bin\webinst.exe";
        // publish -iis -wsdir client_1 -dir "C:\inetpub\wwwroot\client_1" -connstr "Srvr=...;Ref=..."
        var args = $"publish -iis -wsdir {name} -dir \"{publishDir}\" " +
                   $"-connstr \"Srvr=localhost;Ref={name};\"";

        await ExecuteCommandAsync(webinstPath, args);
    }

    private async Task ExecuteCommandAsync(string exe, string args)
    {
        var startInfo = new ProcessStartInfo
        {
            FileName = exe,
            Arguments = args,
            RedirectStandardOutput = true,
            RedirectStandardError = true,
            UseShellExecute = false,
            CreateNoWindow = true
        };

        using var process = Process.Start(startInfo);
        var output = await process.StandardOutput.ReadToEndAsync();
        var error = await process.StandardError.ReadToEndAsync();
        await process.WaitForExitAsync();

        if (process.ExitCode != 0)
        {
            throw new Exception($"1C Error: {error}");
        }
    }
}
```

### 2. Загрузка конфигурации ("Золотой шаблон")

Создать пустую базу мало. Она должна содержать твои HTTP-сервисы, справочники и регистры.
У тебя должен быть подготовленный файл выгрузки `Template.dt`.

Используем пакетный режим Конфигуратора (или `ibcmd`):

```csharp
public async Task LoadConfigurationAsync(string ibName, string dtFilePath)
{
    var v8Path = @"C:\Program Files\1cv8\8.3.xx\bin\1cv8.exe";
    
    // DESIGNER /S localhost\client_1 /LoadDumpFile "C:\Template.dt" /UpdateDBCfg /Out log.txt
    var args = $"DESIGNER /S localhost\\{ibName} /N admin /P password " +
               $"/LoadDumpFile \"{dtFilePath}\" /UpdateDBCfg";

    await ExecuteCommandAsync(v8Path, args);
}
```

### 3. Оркестратор: Hangfire Job

Все это очень медленно (создание + загрузка DT может занять 1-5 минут). Пользователь не должен ждать.

**Стратегия "Теплый пул" (Warm Pool):**
Мы не создаем базу в момент регистрации. Мы держим в запасе 5-10 уже созданных, пустых баз 1С.

**Пайплайн:**
1.  **Background Worker:** Каждые 10 минут проверяет: "Сколько свободных баз в пуле?". Если меньше 5 -> создает новые, грузит DT, публикует. Записывает их в таблицу `MasterDb.SpareOneCInstances`.
2.  **Регистрация клиента:**
    *   Берем готовую базу из пула.
    *   Меняем в ней пароль администратора (через скрипт 1С или `rac`).
    *   Присваиваем её Тенанту.
    *   Выдаем клиенту доступ.

```csharp
public class TenantOnboardingJob
{
    public async Task AssignOneCToTenant(Guid tenantId)
    {
        // 1. Берем свободную базу из пула
        var spareInstance = await _masterDb.SpareOneCInstances
            .Where(x => x.Status == InstanceStatus.Ready)
            .FirstOrDefaultAsync();

        if (spareInstance == null) 
            throw new Exception("Нет свободных баз 1С! Алерт админам!");

        // 2. Создаем пользователя API внутри этой 1С (через V8 Automation или запуск скрипта)
        var apiUser = "api_bot";
        var apiPass = GenerateSecurePassword();
        await _oneCAdmin.CreateUserAsync(spareInstance.Name, apiUser, apiPass);

        // 3. Сохраняем настройки в базу Тенанта
        var tenantSettings = new TenantOneCSettings
        {
            ApiUrl = $"https://1c.mysaas.com/{spareInstance.Name}/hs/api",
            User = apiUser,
            Password = apiPass,
            IsActive = true
        };
        
        using var scope = _scopeFactory.CreateScope();
        var tenantDb = scope.GetTenantDb(tenantId);
        tenantDb.OneCSettings.Add(tenantSettings);
        await tenantDb.SaveChangesAsync();

        // 4. Удаляем из пула
        _masterDb.SpareOneCInstances.Remove(spareInstance);
        await _masterDb.SaveChangesAsync();
    }
}
```

### 4. Сложности и Лицензирование ⚠️

Это самое важное. Технически создать базу легко. Юридически — сложно.

1.  **Лицензии 1С:**
    *   Каждый сеанс (даже HTTP-запрос) кушает клиентскую лицензию или сеанс на сервере.
    *   Вам нужна **Лицензия на сервер 1С (x64)** и многопользовательские клиентские лицензии.
    *   **Важно:** Для SaaS (сдачи в аренду) у 1С есть специальные типы договоров (SaaS/Аренда ПО). Обычные коробки "Бухгалтерии" нельзя сдавать в аренду мульти-тенантом.

2.  **Ресурсы:**
    *   Каждый процесс `rphost` (рабочий процесс 1С) ест память.
    *   100 клиентов = 100 баз. Это потребует мощного кластера (много RAM).

**Альтернатива (Экономная):**
Использовать технологию **1cFresh (Разделение данных)**.
*   Это **ОДНА** база данных и одна публикация.
*   В ней есть колонка-разделитель (ОбластьДанных).
*   Вы создаете "Область" (Tenant) мгновенно, без копирования базы.
*   Все клиенты работают через один URL: `https://1c.mysaas.com/base/a/123` (где 123 — номер области).
*   Это экономит 90% ресурсов сервера.
*   **Но:** Требует, чтобы ваша конфигурация 1С поддерживала БСП (Библиотеку Стандартных Подсистем) и режим разделения данных.

### Итог для Роадмапа:

Если ты делаешь кастомную конфигурацию для управления заказами:
1.  **MVP:** Разворачивай базы руками или скриптом по кнопке админа.
2.  **Prod:** Реализуй "Теплый пул" баз через `rac` + `webinst`.
3.  **HighLoad:** Переписывай конфигурацию 1С под поддержку **Разделения данных (Multitenancy внутри 1С)**, иначе разоришься на серверах.
