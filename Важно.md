# ⚠️ Важные моменты и частые ошибки

> Критически важная информация, которую нужно помнить при разработке SaaS

---

## 🚨 Критические ошибки, которые ломают систему

### 1. ❌ Утечка данных между клиентами

**Самая опасная ошибка в мультитенантной системе:**

```csharp
// ❌ КАТАСТРОФА: клиент увидит чужие данные
var orders = await _db.Orders.ToListAsync();

// ✅ ПРАВИЛЬНО: всегда фильтруй по TenantId
var orders = await _db.Orders
    .Where(o => o.TenantId == _tenantService.GetTenantId())
    .ToListAsync();
```

**Защита:**
- Используй глобальные фильтры EF Core для автоматической фильтрации
- Никогда не делай запросы без явного указания TenantId
- Тестируй изоляцию данных в каждом запросе

---

### 2. ❌ Captive Dependency в DI

**Singleton сервис захватывает Scoped зависимость:**

```csharp
// ❌ УТЕЧКА ПАМЯТИ: DbContext никогда не освободится
public class CacheService : ISingleton
{
    private readonly AppDbContext _db; // Scoped!
}

// ✅ ПРАВИЛЬНО: используй IServiceScopeFactory
public class CacheService : ISingleton
{
    private readonly IServiceScopeFactory _scopeFactory;
    
    public async Task DoWork()
    {
        using var scope = _scopeFactory.CreateScope();
        var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
        // DbContext корректно освободится
    }
}
```

---

### 3. ❌ Блокировка потоков через .Result или .Wait()

**Thread Pool Starvation - приложение зависнет под нагрузкой:**

```csharp
// ❌ КАТАСТРОФА: блокирует поток
var result = httpClient.GetAsync(url).Result;

// ✅ ПРАВИЛЬНО: async/await до самого верха
public async Task<IActionResult> GetData()
{
    var result = await httpClient.GetAsync(url);
    return Ok(result);
}
```

**Правило:** Если метод async - весь путь до контроллера должен быть async.

---

### 4. ❌ new HttpClient() вместо IHttpClientFactory

**Утечка сокетов и исчерпание портов:**

```csharp
// ❌ УТЕЧКА: сокеты не освобождаются
using var client = new HttpClient();
await client.GetAsync(url);

// ✅ ПРАВИЛЬНО: используй фабрику
private readonly HttpClient _http;
public MyService(IHttpClientFactory factory)
{
    _http = factory.CreateClient("MyApi");
}
```

---

### 5. ❌ Общий ключ кэша для всех клиентов

**Клиент увидит чужие данные:**

```csharp
// ❌ ОПАСНО: все клиенты получат одни данные
var products = await _cache.GetStringAsync("products");

// ✅ ПРАВИЛЬНО: ключ с TenantId
var key = $"tenant:{tenantId}:products";
var products = await _cache.GetStringAsync(key);
```

## ⚡ Производительность

### 1. N+1 проблема в EF Core

```csharp
// ❌ ПЛОХО: N+1 запросов
var orders = await _db.Orders.ToListAsync();
foreach (var order in orders)
{
    var client = await _db.Clients.FindAsync(order.ClientId); // Запрос на каждую итерацию!
}

// ✅ ХОРОШО: один запрос с Include
var orders = await _db.Orders
    .Include(o => o.Client)
    .ToListAsync();
```

### 2. Загрузка всех данных вместо проекции

```csharp
// ❌ ПЛОХО: загружаем все поля и навигации
var orders = await _db.Orders
    .Include(o => o.Items)
    .Include(o => o.Client)
    .ToListAsync();

// ✅ ХОРОШО: проекция только нужных полей
var orders = await _db.Orders
    .Select(o => new OrderDto
    {
        Id = o.Id,
        Number = o.Number,
        ClientName = o.Client.Name
    })
    .ToListAsync();
```

## 🔐 Безопасность

### 1. Всегда проверяй права доступа

```csharp
// ❌ ОПАСНО: любой может получить любой заказ
[HttpGet("{id}")]
public async Task<Order> GetOrder(Guid id)
{
    return await _db.Orders.FindAsync(id);
}

// ✅ ПРАВИЛЬНО: проверка TenantId и прав
[HttpGet("{id}")]
[Authorize]
public async Task<Order> GetOrder(Guid id)
{
    var tenantId = GetTenantId();
    var order = await _db.Orders
        .Where(o => o.Id == id && o.TenantId == tenantId)
        .FirstOrDefaultAsync();
    
    if (order == null) throw new NotFoundException();
    return order;
}
```

### 2. Валидация входных данных

```csharp
// ❌ ОПАСНО: SQL Injection, XSS
var query = $"SELECT * FROM Orders WHERE Number = '{userInput}'";

// ✅ ПРАВИЛЬНО: параметризованные запросы через EF Core
var orders = await _db.Orders
    .Where(o => o.Number == userInput)
    .ToListAsync();
```

## 📝 Логирование

### 1. Структурированное логирование

```csharp
// ❌ ПЛОХО: строковая конкатенация
_logger.LogInfo("Заказ " + orderId + " создан для клиента " + clientId);

// ✅ ХОРОШО: структурированное логирование
_logger.LogInformation("Заказ {OrderId} создан для клиента {ClientId}", orderId, clientId);
```

### 2. Всегда логируй TenantId

```csharp
_logger.LogInformation(
    "Синхронизация заказов для тенанта {TenantId} начата. Период: {From} - {To}",
    tenantId, from, to
);
```

## 🗄️ Работа с БД

### 1. Транзакции для критичных операций

```csharp
// ✅ ПРАВИЛЬНО: атомарная операция
using var transaction = await _db.Database.BeginTransactionAsync();
try
{
    await CreateOrder(order);
    await UpdateInventory(items);
    await transaction.CommitAsync();
}
catch
{
    await transaction.RollbackAsync();
    throw;
}
```

### 2. Миграции для всех клиентских БД

```csharp
// ❌ ПЛОХО: миграция только для одной БД
dotnet ef database update

// ✅ ХОРОШО: автоматическая миграция всех БД
foreach (var tenant in tenants)
{
    using var context = new TenantDbContext(tenant.ConnectionString);
    await context.Database.MigrateAsync();
}
```

## 🎯 Чек-лист перед деплоем

- [ ] Все запросы фильтруются по TenantId
- [ ] Нет `.Result` или `.Wait()` в async методах
- [ ] Используется `IHttpClientFactory` для HTTP клиентов
- [ ] Ключи кэша содержат TenantId
- [ ] Нет N+1 проблем в запросах
- [ ] Все контроллеры имеют `[Authorize]`
- [ ] Логирование структурированное с TenantId
- [ ] Миграции применены ко всем клиентским БД
- [ ] Есть обработка ошибок и fallback
- [ ] Настроен мониторинг и алерты
