Качество кода (Code Quality) в ASP.NET Core — это не только про «красиво написанные строчки». Это про то, чтобы приложение **не падало под нагрузкой**, **не текло по памяти** и **легко изменялось**.

Для маленькой команды, которая делает сложный SaaS, важно соблюдать прагматичные правила. Вот **Золотой Стандарт 2025 года** для ASP.NET Core.

---

### 1. 💉 Правильная работа с Dependency Injection (DI)

Это место, где новички делают ошибки, убивающие приложение.

#### ❌ Ошибка: Captive Dependency (Захваченная зависимость)
Никогда не внедряй сервис с коротким временем жизни (`Scoped`) в сервис с долгим (`Singleton`).
*   Если Singleton-сервис (например, кэш) захватит Scoped-сервис (например, DbContext), то DbContext никогда не очистится. Память утечет, соединения с БД закончатся.

#### ✅ Правило:
*   **Singleton** может зависеть только от **Singleton**.
*   **Scoped** может зависеть от **Singleton** и **Scoped**.
*   Если Singleton'у нужен Scoped — используй `IServiceScopeFactory`.

```csharp
// В Singleton сервисе
using var scope = _scopeFactory.CreateScope();
var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
```

### 2. ⚡ Асинхронность (Async/Await) без блокировок

ASP.NET Core рассчитан на асинхронность. Любая блокировка потока убивает производительность (Thread Pool Starvation).

#### ❌ Никогда не пиши:
*   `.Result`
*   `.Wait()`
*   `Thread.Sleep()`

#### ✅ Всегда используй:
*   `await` до самого верха (до Контроллера).
*   **CancellationToken**. Это обязательно для высоконагруженных систем. Если пользователь закрыл браузер, запрос к БД должен отмениться.

```csharp
// Всегда пробрасывай ct
public async Task<List<Order>> GetOrders(CancellationToken ct)
{
    // EF Core поддерживает отмену
    return await _db.Orders.ToListAsync(ct); 
}
```

### 3. 🛡️ "Тонкие" Контроллеры (Thin Controllers)

Контроллер — это просто "регулировщик". Он не должен содержать `if`, циклов и бизнес-логики.

#### ✅ Ответственность контроллера:
1.  Принять HTTP запрос.
2.  Вызвать валидатор (FluentValidation).
3.  Вызвать `Mediator` или `Service`.
4.  Вернуть HTTP статус (200 OK, 400 Bad Request).

```csharp
[HttpPost]
public async Task<IActionResult> CreateOrder(CreateOrderDto dto)
{
    // Вся логика ушла в Handler
    var orderId = await _mediator.Send(new CreateOrderCommand(dto));
    return Ok(orderId);
}
```

### 4. ⚙️ Конфигурация через Options Pattern

Никаких `_config["MySettings:ApiKey"]` в коде! Это строки, которые легко опечатать, и их трудно тестировать.

#### ✅ Используй IOptions<T> и Валидацию при старте

```csharp
// 1. Класс настроек
public class OzonSettings 
{
    [Required] public string ApiKey { get; set; }
    [Range(1, 10)] public int RetryCount { get; set; }
}

// 2. Program.cs (Валидация при запуске приложения!)
builder.Services.AddOptions<OzonSettings>()
    .BindConfiguration("Ozon")
    .ValidateDataAnnotations()
    .ValidateOnStart(); // Приложение упадет сразу, если забыл конфиг

// 3. Использование
public class OzonService(IOptions<OzonSettings> options) { ... }
```

### 5. 🛑 Глобальная обработка ошибок (Global Exception Handling)

Никаких `try-catch` в каждом контроллере! Это мусорный код.

#### ✅ Используй Middleware или IExceptionHandler (новое в .NET 8)
Весь код пишется так, будто ошибок не бывает. Если ошибка случается, она всплывает в глобальный перехватчик, который:
1.  Логирует ошибку (Stack Trace).
2.  Возвращает клиенту красивый JSON (ProblemDetails, RFC 7807).

```csharp
// Program.cs
app.UseExceptionHandler(); // Встроенный механизм

// CustomExceptionHandler.cs
public async ValueTask<bool> TryHandleAsync(...)
{
    // Логируем
    _logger.LogError(exception, "Ошибка");
    
    // Отвечаем стандартом
    httpContext.Response.StatusCode = 500;
    await httpContext.Response.WriteAsJsonAsync(new ProblemDetails { ... });
    
    return true;
}
```

### 6. 📝 Структурное логирование (Structured Logging)

Никогда не склеивай строки в логах.
❌ `_logger.LogInfo("Заказ " + id + " создан");`

Это невозможно искать в системах аналитики (Elasticsearch, Seq, Grafana Loki).

#### ✅ Используй плейсхолдеры (Serilog):
```csharp
// Фигурные скобки создают индексируемое поле OrderId
_logger.LogInformation("Заказ {OrderId} создан для клиента {ClientId}", order.Id, client.Id);
```
Теперь ты можешь искать: `select * where OrderId = 123`.

### 7. ✅ Валидация (FluentValidation)

Не засоряй DTO атрибутами `[Required]` (Data Annotations). Логика валидации часто сложнее, чем просто "не пустое".

Используй **FluentValidation**.

```csharp
public class CreateOrderValidator : AbstractValidator<CreateOrderDto>
{
    public CreateOrderValidator()
    {
        RuleFor(x => x.Email).EmailAddress();
        RuleFor(x => x.Items).NotEmpty();
        // Можно даже лезть в базу (осторожно)
    }
}
```
Подключи библиотеку, которая автоматически проверяет DTO на входе в контроллер и отдает 400 Bad Request.

### 8. 🧪 Тестирование: Прагматичный подход

Для маленькой команды 100% покрытие Unit-тестами — это смерть времени.

#### ✅ Пирамида тестов для SaaS:
1.  **Integration Tests (самое важное):** Используй **Testcontainers**. Поднимается реальная БД в Docker, прогоняется сценарий API, БД уничтожается. Это дает гарантию, что SQL-запросы, маппинг и логика работают.
2.  **Unit Tests:** Только для сложной бизнес-логики внутри Доменных моделей (расчет скидок, налогов, статусов). Не тестируй простые CRUD сервисы.

---

### 9. 🧹 Единый стиль кода (EditorConfig)

Чтобы не спорить на ревью "где ставить скобочки", добавь файл `.editorconfig` в корень проекта.

```ini
[*.cs]
indent_style = space
indent_size = 4
csharp_style_var_for_built_in_types = true:suggestion
```
IDE сама отформатирует код при сохранении.

### Итоговый чек-лист Code Quality 2025:

| Аспект | Правило |
|---|---|
| **DI** | Нет Singleton -> Scoped зависимостей. |
| **Async** | Везде `await` и `CancellationToken`. Нет `.Result`. |
| **Controllers** | Только вызов MediatR/Service. Никакой логики. |
| **Exceptions** | Глобальный Handler. `ProblemDetails` response. |
| **Config** | `IOptions<T>` + `ValidateOnStart()`. |
| **Logs** | Serilog + Структурное логирование `{Param}`. |
| **Validation** | FluentValidation (отдельные классы). |
| **Data Access** | Никаких IRepository. DbContext + Projections. |
| **Testing** | Упор на Integration Tests с Testcontainers. |

Соблюдение этих правил гарантирует, что проект будет легко поддерживать даже через 2 года.
